Grounding context

为什么 R2R 可以做简单

R2R 路径指令通常按顺序描述若干可观察 landmark、转弯动作和房间切换。V1 不需要建立完整地图，只需要让 JanusVLN 看到当前 subgoal 的入口位置、最近一次相关转折或 landmark，以及连续的普通历史。

Save policy

关键帧怎么保存

1

初始帧

episode 的 step 0 固定保存，不参与淘汰。

2

阶段入口帧

切换到新 subgoal 时保存当前帧。上一阶段完成帧通常可直接作为下一阶段入口帧，避免重复。

3

转向帧

JanusVLN 第一次进入连续 TURN_LEFT 或 TURN_RIGHT 动作段时保存一张；连续相同 TURN 不重复保存。

4

阶段完成帧

Verifier 判断当前 subgoal 完成时保存，用于连接当前阶段与下一阶段。

5

长直行兜底

距离上一次保存超过20 step 时保存一张，防止长走廊完全没有中间视觉记录。

6

简单去重

最小间隔5 step；阶段入口和完成帧可以绕过该间隔。episode 最多保存64张。

每张关键帧只保存以下简单 metadata：

{
  "scene_id": "...",
  "episode_id": "...",
  "step_id": 42,
  "subgoal_id": 1,
  "subgoal_text": "turn left and enter the kitchen",
  "landmarks": ["kitchen"],
  "save_reason": "stage_entry | turn | stage_complete | coverage_gap",
  "image_path": "..."
}
Retrieval policy

关键帧怎么检索

只在当前 episode 的过去帧中检索，最多返回2张，不使用复杂向量数据库。

  1. 优先取当前 subgoal_id 的阶段入口帧。
  2. 再取当前 subgoal 中最新的转向帧或完成相关帧。
  3. 如果当前阶段没有足够关键帧，用上一 subgoal 的完成帧补一张。
  4. 如果仍不足，不强行补关键帧，保留普通历史帧。
  5. 候选多于2张时，先按 landmark 关键词重合过滤，再选择最新的一张。
  6. 选完以后按照 step_id 排序，保持历史时间顺序。
candidates = prior_episode_keyframes
current = candidates where subgoal_id == current_subgoal_id

K1 = stage_entry(current)
K2 = latest(turn_or_stage_complete(current))

if K1 or K2 missing:
    use previous_subgoal_completion

return at most 2 keyframes, sorted by step_id
核心原则：检索不到相关帧时宁可使用普通历史，也不要塞入旧阶段或不相关 landmark 的关键帧。
Fixed visual input

9张图像怎么组成

先从原始轨迹得到1张初始帧、7张中间历史帧和1张当前帧。若检索到关键帧，只替换7个中间槽位中的最多2个。

没有关键帧
[Initial, H1, H2, H3, H4, H5, H6, H7, Current]
检索到1张
[Initial, H1, H2, K1, H3, H4, H5, H6, Current]
检索到2张
[Initial, H1, K1, H2, H3, K2, H4, H5, Current]

实际输入前对7张中间帧统一按 step_id 排序，以上位置只是表达“最多替换2张”，不是强制固定索引。

Rejection summary

从上一版删除的复杂设计

删除项原因
六类 evidence roles对 R2R V1 太细，改为入口、转向、完成三类主要事件。
集合效用函数需要多项权重，难解释和调参；改为固定优先级。
动态2–5张关键帧配额输入变化过多；固定最多2张更容易消融。
边际效用替换V1 先保留简单 episode cap；R2R 一般不容易达到64张。
Transition Capsule 成对确认先只保存转向动作段首帧和阶段完成帧。
视觉 embedding / DPP / CLIP top-k不是 R2R V1 的必要条件；先用 subgoal ID 和 landmark 关键词。
失败负向记忆和 replanning继续留到 V2。
